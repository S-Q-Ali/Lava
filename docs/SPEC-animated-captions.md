# SPEC — M6 module 5: `animated-captions`

## Goal
Layer five named caption animation treatments — kinetic, manga, cinematic, meme,
storytelling — onto the existing caption pipeline, generated **entirely with
libass ASS tags** (`{\t}`, `{\fad}`, `{\fscx\fscy}`, `{\alpha}`) in the pure
backend ASS generator, selectable from the existing style/preset/panel surfaces.

## Scope

### In scope
- `animation` field on the caption style contract, the `Preset` schema, the
  `PresetDraft` editor model, and the render wire (`captionToWire`).
- Backend ASS generation for the five named treatments plus `none` (default),
  rendered as deterministic inline tag wrappers in `build_dialogue_line`
  (`backend/src/lava_backend/captions.py`), verified by byte-exact tests.
- Kinematic projection uses the existing `words[]` per-word timing when
  present and falls back to an even split of the line across its duration.
- Frontend: `CaptionAnimation` type + `ANIMATION_OPTIONS`, four M5 presets
  (`manga`, `cinematic`, `meme`, `storytelling`) gain their matching
  `animation`, `parsePreset`/`captionStyleFromPreset`/`captionToWire` pass the
  field through, and `TemplateEditorPanel` gains an Animation control.
- Karaoke precedence is preserved (a karaoke flag renders the `\k` sweep and
  wins over the treatment wrapper).

### Out of scope — deferred to M8 preview overlay
- True manga **speed lines** (pixel-space vector drawing, `{\p}` streaks) and
  true cinematic **letterbox bars** — both need resolved-playback pixel
  placement the text ASS generator cannot measure; recorded as deferred
  follow-ups. Manga renders as an impact-frame scale/alpha punch, cinematic as
  fade + slow scale, per the recipes below.
- Per-word manual timing editing UI (render already consumes `words[]` timing
  generated by the voice pipeline; a manual timing editor is timeline work).
- Motion preview in the timeline / editor canvas (M8 owns the preview overlay).

## Assumptions
1. Animations are a **style/preset property**, not a per-caption property —
   matching M6 open question 3's default (a caption uses its resolved style's
   animation; per-word timing already rides the existing `words[]`).
2. The backend ASS generator is the single place that emits animation tags
   (keeps render byte-parity tests simple and honest).
3. `animation` is an enum string, never free-form; invalid values reject at
   the same layer as the other style/preset fields (422/style error).
4. `none` is the default everywhere; existing M5 output is byte-identical
   unless a preset explicitly opts into animation.
5. Treatments compose with existing uppercase, rtl and outline handling; rtl
   wraps outside the animation wrapper (per current `{\rtl}` prefix position).
6. `karaoke` + `animation` simultaneously set → karaoke wins (documented, not
   an error).

## Recipes (semantics; exact strings derive from RED tests in slice 1)
- `kinetic` — per word: `{alpha&HFF&}{fscx0\fscy0\t(D, D+300, 1, \alpha&H00&\fscx100\fscy100)}` where `D` is the word's ms offset from the line start.
- `manga` — impact punch: `200%`→`100%` scale + alpha fade-in across the first ~180 ms of the line.
- `cinematic` — `{\fad(400,400)}` + `96%`→`100%` scale across the full duration.
- `meme` — punch/wobble: three successive non-overlapping scale `\t` ramps (e.g. 108→100→106→100) in the first ~180 ms.
- `storytelling` — `{\fad(600,600)}` + `98%`→`100%` scale across the full duration.
